# Частичная перерисовка при смене выделения: документация правок форка

Этот документ описывает, **что мы доработали в форке glide** в #61: при смене выделения
(`selection`), регионов подсветки (`highlightRegions`) и фокуса (`isFocused`) перерисовываются
только затронутые области, а не весь экран. Это продолжение #60 (подсказка `changes` у
`rowHeight`), вторая часть борьбы с фризами на больших таблицах.
Здесь: в чём проблема, что было нативным и что добавили мы, как считаются области, откаты на полный
кадр, поведение со слитыми блоками, замечания для потребителя, карта кода и тесты.

**Что меняется для потребителя.** Публичные пропсы прежние, но меняется договор отрисовки: раньше
при стабильной `getCellContent` любая смена выделения давала кадр целиком, теперь перерисовываются
только области выделения. Если `getCellContent` или `drawCell` читают выделение (или то, что от него
зависит) не из аргументов, а из ref, ячейки вне этих областей останутся прежними. Такие ячейки
потребитель дорисовывает сам через `updateCells`, см. раздел 8.

---

## 1. Проблема и решение

Нативно любая смена `selection`, `highlightRegions` или `isFocused` означала для `drawGrid`
«поменялось всё»: `computeCanBlit` возвращал `false`, сдвиг прошлого кадра запрещался, и экран
рисовался целиком. На таблице в 1000 колонок клик по ячейке это два полных кадра (сначала выделение,
затем фокус), каждый шаг протяжки выделения ещё один.

```
нативно: клик по ячейке                   форк: клик по ячейке
┌──────────────────────────┐              ┌──────────────────────────┐
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │              │                          │
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │  весь экран  │      ┌──┐                │  прежняя ячейка
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │  два раза    │      └──┘     ┌──┐       │  и новая ячейка,
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │              │               └──┘       │  с запасом 8 px
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒ │              │                          │
└──────────────────────────┘              └──────────────────────────┘
```

**Решение:** если между кадрами сменились только выделение, регионы подсветки или фокус, а всё
остальное (данные, темы, размеры, колонки, высоты строк) прежнее, прошлый кадр берётся как при
прокрутке, а поверх него перерисовывается объединение прежних и новых областей выделения. Области
считает новый модуль `data-grid-render.selection-regions.ts`, передаёт их в `blitLastFrame` через
параметр `extraRegions`, дальше работает обычный проход отрисовки под клипом по областям.

## 2. Что нативное в glide, а что добавили МЫ

| Уже было в glide (нативное) | Добавили МЫ (форк) |
|---|---|
| `computeCanBlit`: смена `selection`, `highlightRegions`, `isFocused` даёт `false` | `isSelectionOnlyChange`: «кроме них ничего не менялось», тогда сдвиг кадра разрешается вручную |
| `blitLastFrame` отдаёт полосы прокрутки | параметр `extraRegions` (список областей поверх сдвинутого кадра; в #60 была одна область) |
| `drawHighlightRings` и `drawFillHandle` рисуют сразу при вызове и возвращают функцию дорисовки | параметр `drawNow`: в кадре тела обводки и маркер растяжения рисуются только после ячеек |
| шапка рисуется заново при любом сдвиге кадра | `selectionHeaderChanged`: шапка только при смене колонок выделения |
| точечная дорисовка (`damage`) трогает только ячейки | `repaintBlankArea`: пустая область правее колонок перекрашивается по темам строк |
| `computeCanBlit` не сравнивал `drawFocus`, `fillHandle`, `disabledRows`, `hasAppendRow` | сравнивает; `BlitData.dpr` для отката при смене масштаба холста |

Без смены выделения код идёт прежним путём; обводки в кадре тела теперь рисуются один раз, а не
два (это касалось и обычной прокрутки, см. раздел 6).

## 3. Как проходит кадр

```
[1] drawGrid: canBlit = computeCanBlit(arg, lastArg)          нативно: false при смене выделения
        |
[2] НАШЕ: selectionChange = canBlit === false
          && renderStrategy !== "direct" && есть lastArg и lastBlitData
          && isSelectionOnlyChange(arg, lastArg)
          если да, canBlit = true
        |
[3] общие откаты (были и до нас): смена dpr, прилип или отлип элемент (pinnedColumnsEnd,
    pinnedRowsCount), липкий блок на экране при вертикальной прокрутке; все дают canBlit = false
        |
[4] НАШЕ: selectionRegions = getSelectionChangeRegions(...)
          undefined: кадр целиком (canBlit = false)
          []: на экране от смены ничего не зависит
          [...]: области с запасом
        |
[5] #60: changedRowsRegion по подсказке rowHeight (складывается с областями выделения)
        |
[6] шапка: drawHeaderTexture, если canBlit !== true, сдвиг по X, сменились признаки обводок и
    фокуса в шапке, selectionHeaderChanged(selection, lastArg.selection) или сменились регионы
    с обводкой в первой видимой строке
        |
[7] НАШЕ: selectionRegions пустой, высоты и прокрутка прежние: тело не трогаем, запоминаем
    только признаки шапки в lastBlitData и выходим
        |
[8] blitLastFrame(..., extraRegions = selectionRegions + changedRowsRegion) сдвигает кадр
    (если есть сдвиг) и отдаёт drawRegions = полосы прокрутки + наши области
        |
[9] обычный проход: клип по drawRegions, ячейки, линии сетки, затем highlightRedraw,
    focusRedraw, highlightAboveRedraw (обводки и маркер растяжения после ячеек)
```

### 3.1 `isSelectionOnlyChange`

Если `selection`, `highlightRegions` и `isFocused` все те же, ответ `false` (менять нечего, это не
наш случай). Иначе вызывается `computeCanBlit(current, last с подменёнными selection,
highlightRegions, isFocused)`: если он возвращает ровно `true`, значит кроме этих трёх полей ничего
не менялось. Ответ-число (ресайз одной колонки) за `true` не считается.

### 3.2 `getSelectionChangeRegions`

Собирает список диапазонов ячеек (`CellRange`, границы включительно):

- прежнее выделение: ячейка `current.cell` (отдельной областью, только если не лежит в
  `current.range`), `current.range`, все диапазоны `rangeStack`;
- новое выделение, если оно другое: то же;
- регионы подсветки, если массив другой: сравнение по позиции в массиве и ключу
  (`range`, `color`, `style`, `drawAboveSelection`). Регион на той же позиции с тем же ключом
  не трогаем, остальные прежние и новые перерисовываем. Позиция важна: регионы ложатся друг на
  друга по порядку;
- при смене фокуса без смены выделения: области текущего выделения (без фокуса выбранные ячейки
  красятся иначе).

Дальше каждый диапазон расширяется до слитых блоков (раздел 5), обрезается по видимым строкам
(верх каждой строки считается от `cellYOffset` с учётом `translateY`, низ последней видимой строки
по низу экрана), по видимым колонкам (прилипшие на своих местах, прокручиваемые обрезаны по краю
закреплённой зоны `pinnedEnd`) и превращается в прямоугольник в пикселях с запасом `pad` по всем
сторонам, обрезанный по холсту.

Запас `selectionRegionPad(fillHandle)`: не меньше `SELECTION_REGION_PAD = 8` px под обводки
регионов и сглаженные края; при включённом маркере растяжения считается от его размера:
`max(8, ceil(size / 2 + max(|offsetX|, |offsetY|) + outline + 1))`.

Области, целиком лежащие внутри другой, выбрасываются (при протяжке прежний диапазон лежит в
новом). Если оставшиеся области занимают больше `MAX_AREA_SHARE = 60%` площади тела таблицы (без
шапки), кадр целиком дешевле: ответ `undefined`.

Пустой список значит, что на экране от смены ничего не зависит (выделение за кадром, новый массив
регионов с тем же содержимым): тело не перерисовывается вовсе.

### 3.3 `selectionHeaderChanged`

Шапка отмечает выбранные колонки, колонку выбранной ячейки и колонки диапазонов (включая стек), а
выделение заголовка идёт отрицательной строкой. Поэтому шапка рисуется заново, когда:

- сменился набор выбранных колонок (`columns`);
- выделение появилось или сброшено (`current` был или стал `undefined`);
- сменилась колонка ячейки (`cell[0]`) или одна из ячеек в заголовке (`cell[1] < 0`);
- сменились `range.x` или `range.width`;
- сменилась длина `rangeStack` или любой его прямоугольник.

Смена только строк (клик ниже в той же колонке, протяжка по строкам, стрелки вверх и вниз) шапку
не трогает. Отдельно: при смене регионов подсветки шапка рисуется, если обводка региона лежит или
лежала в первой видимой строке (`mustDrawHighlightRingsOnHeader`): верхняя линия такой обводки
живёт на холсте шапки.

## 4. Откаты на полный кадр

`getSelectionChangeRegions` возвращает `undefined`, и кадр рисуется целиком, как раньше, когда:

- на экране прилипшие строки (`pinnedRowsCount > 0`) или липкий слитый блок (`stickySpanInView`,
  `spanAlign.sticky`);
- сменился набор выбранных строк или колонок (`selection.rows`, `selection.columns`): красится
  вся строка или колонка вместе с пустой областью правее колонок;
- сменился фокус при выбранных строках или колонках;
- областей больше `MAX_REGIONS = 64` (клип и проверка каждой ячейки по областям дороже кадра);
- хотя бы один диапазон задевает итоговые строки (`freezeTrailingRows`): они прижаты к низу экрана
  и живут отдельно от строк тела;
- расширение до слитых блоков не сошлось за `MAX_SPAN_PASSES = 8` проходов;
- области занимают больше 60% площади тела.

Вне модуля областей кадр целиком дают: смена `dpr` (присвоение `canvas.width` очищает холст,
сдвигать нечего), прилипание или отлипание липкого элемента, вертикальная прокрутка при липком
блоке на экране, режим `direct`, и любая смена чего-то ещё в `computeCanBlit` вместе с выделением
(`getCellContent`, `getRowThemeOverride`, колонки, высоты без подсказки и так далее).

## 5. Слитые блоки (`expandToSpans`)

Слитый блок (`span`, `spanRows`) красится целиком, поэтому область, задевшая блок, обязана
растянуться до его границ, иначе часть блока останется с прежним фоном и прежним маркером
растяжения. Сложность в том, что диапазон может задевать блок ячейкой **за кадром**: прокрученной
вверх, ушедшей под закреплённую зону колонок или за правый край. У такого диапазона видимой части
нет, спросить «его» ячейки нельзя, а ячейки за кадром спрашивать нельзя (с `experimental.strict`
потребитель за них не отвечает).

```
                                        видимые колонки: A B C D, видимые строки: 5..9
      A   B   C   D                     диапазон: ячейка B3 (прокручена за верхний край)
  3   ·  [X]                            блок B2..B7 задевает и диапазон, и экран
  4   ·  [ ]                            видимых строк у диапазона нет, опрашивается ближайшая
 ─────────────────────── верх экрана    видимая строка ниже (5) в колонках B и соседних A, C:
  5   ·  [ ]  ·   ·                     B5 входит в блок, диапазон растёт до B2..B7,
  6   ·  [ ]  ·   ·                     его видимая часть B5..B7 попадает в область
  7   ·  [ ]  ·   ·
  8   ·   ·   ·   ·
  9   ·   ·   ·   ·
```

Спрашиваются только видимые ячейки (`probeColumns`, `probeRows`): видимые колонки диапазона и
ближайшая видимая колонка слева и справа от него, видимые строки диапазона и ближайшая видимая
строка выше и ниже. В крайних колонках этого набора опрашиваются все строки набора, в остальных
только крайние строки. Блок, который пересекает и диапазон, и экран, но выходит за диапазон,
обязательно содержит одну из этих ячеек. `growToSpan` растягивает диапазон до `span`/`spanRows`
ячейки, только если блок задевает диапазон; соседние блоки мимо диапазона область не трогают.
Повторяется, пока границы растут (цепочки блоков тянут друг друга), не больше `MAX_SPAN_PASSES`
раз.

## 6. Обводки и маркер растяжения рисуются один раз (`drawNow`)

`drawHighlightRings` и `drawFillHandle` нативно рисовали сразу при вызове и возвращали функцию
повторной дорисовки после ячеек. В полном кадре первый слой перекрывала заливка фона, а на
сдвинутом прошлом кадре (прокрутка, теперь и смена выделения) обводка ложилась второй раз поверх
уже нарисованной, и полупрозрачные или сглаженные при дробном DPR края темнели с каждым частичным
кадром. Найдено попиксельной сверкой частичного кадра с полным: край региона 50% против 75%.

Новый параметр `drawNow` (по умолчанию `true`): в кадре тела `drawGrid` передаёт `false` и рисует
обводки (`highlightRedraw`, `highlightAboveRedraw`) и маркер растяжения (`focusRedraw`) только
после ячеек и линий сетки. То же в damage-пути со слитыми ячейками. В шапке обводки рисуются сразу,
как раньше.

В простом damage-пути (без слитых ячеек) обводки нативно не перерисовывались: они лежат на крайних
пикселях ячеек и жили за счёт того, что содержимое ячейки не заходило на крайний пиксель. Ячейка,
залитая до края, при наведении через `updateCells` их затирала. Теперь после ячеек обводки
перерисовываются под клипом по повреждённым ячейкам в том же порядке, что в полном кадре: обычные
регионы (включая рамку фокуса и диапазоны), маркер растяжения, регионы с `drawAboveSelection`.

---

## 7. Пустая область в damage-пути (`repaintBlankArea`)

В полном кадре фон строки (наведение, зебра, отмеченная строка) красится и в пустой области правее
последней колонки (`drawBlanks`). Точечная дорисовка (`damage`, то есть `updateCells`) обновляла
только ячейки: при наведении через `updateCells` в узкой таблице серая полоса правее колонок
застревала на прежней строке. Теперь обе ветки damage-пути перекрашивают пустую область: заливка
`theme.bgCell`, затем `drawBlanks` по темам строк под клипом по этой области. Делается только когда
есть `getRowThemeOverride`, дорисовка попала в видимую область и правее колонок есть место.

## 8. Замечания для потребителя

- Выигрыш есть только если потребитель между кадрами **не меняет** `getCellContent`,
  `getRowThemeOverride` и массив колонок. Новая функция `getCellContent` на каждый клик (так было у
  dais-ui (TableCanvas) до своей правки) отключает путь полностью: `computeCanBlit` видит смену
  данных и даёт кадр целиком.
- Массив колонок: при более ста колонках новый массив всегда даёт полный кадр (`computeCanBlit`
  не сравнивает колонки поштучно). До ста колонок сравнение поштучно, допускается смена ширины
  одной колонки.
- Остальные поля `computeCanBlit` (`drawFocus`, `fillHandle`, `disabledRows`, `hasAppendRow`,
  тема, `verticalBorder`, `getCellBorder` и так далее) тоже должны быть стабильны по ссылке.
- Выделение строк и колонок, итоговые строки, прилипшие строки по-прежнему дают полный кадр.
- Если вид ячейки зависит от выделения, а читает его `getCellContent` или `drawCell` из ref (так
  удобнее, чтобы не пересоздавать `getCellContent` на каждый клик), glide не узнает, какие ячейки
  от смены выделения зависят, и перерисует только области выделения. Остальные такие ячейки
  (например, вся строка выделенной ячейки или подсвеченная шапка строки) потребитель дорисовывает
  сам через `updateCells` после смены выделения. В dais-ui (TableGlide) это делают хуки
  `useActiveRowsRedraw` и `useActiveHeadersRedraw`.
- Для dais-ui (TableCanvas) на 1000 колонках перерисовка шапки на каждый кадр выделения стоила
  примерно четверть кадра; `selectionHeaderChanged` убирает её при переходах по строкам.
