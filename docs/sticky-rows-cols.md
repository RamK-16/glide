# Липкие строки и колонки — документация правок форка

Этот документ описывает пропсы `stickyRows` и `stickyColumns`: строки и колонки, которые прилипают
к краю при прокрутке, как `position: sticky`. Нативно в glide есть только префикс `freezeColumns`
(первые N колонок закреплены всегда) и `freezeTrailingRows` (последние строки снизу).

---

## 1. Поведение

Липкий элемент стоит на своём месте, пока при прокрутке не дойдёт до своего слота в закреплённой
зоне. Слот — сумма размеров липких элементов перед ним. Дальше элемент остаётся в слоте, а
следующие прилипают под (правее) него.

```
до прокрутки            прокрутили на 4 строки       прокрутили на 9 строк
┌──────────────┐        ┌──────────────┐             ┌──────────────┐
│ шапка        │        │ шапка        │             │ шапка        │
├──────────────┤        ├──────────────┤             ├──────────────┤
│ 0            │        │ 2 (липкая)   │ ← прилипла  │ 2 (липкая)   │
│ 1            │        ├──────────────┤             │ 6 (липкая)   │ ← прилипла
│ 2 (липкая)   │        │ 5            │             ├──────────────┤
│ 3            │        │ 6 (липкая)   │ ← ещё на    │ 11           │
│ …            │        │ 7            │   своём     │ 12           │
```

- `freezeColumns` работает как раньше и сочетается со `stickyColumns`. Без `sticky*` поведение и
  пиксели прежние (все существующие тесты проходят без правок).
- Индексы в координатах данных, без колонки маркеров строк. Порядок и дубли не важны, индексы вне
  таблицы отбрасываются. Липкие строки среди закреплённых снизу (`freezeTrailingRows`) игнорируются.
- Группы колонок в шапке разрываются на границе закреплённой зоны, как в Excel.
- Слитый по строкам блок (`spanRows`), задевающий прилипшую строку, режется на фрагменты: текст рисует
  закреплённый фрагмент, прокручиваемая часть — только фон и границы.
- `scrollTo` ставит цель под прилипшими элементами: отступ равен сумме липких элементов перед целью
  (ровно столько будет закреплено, когда цель встанет у края).
- `onVisibleRegionChanged` отдаёт липкие колонки и строки в `extras.freezeRegions`, чтобы потребитель
  загрузил для них данные.

## 2. Как устроено

Ключевой инвариант: закреплённые сейчас элементы — всегда префикс отсортированного списка липких.
Если элемент k упёрся в свой слот, то любой липкий j < k тоже упёрся: между ними не меньше липких
пикселей, чем разница их слотов. Поэтому закреплённая зона — сплошная полоса, а всё остальное, включая
ещё не прилипшие липкие элементы, — обычная прокрутка. Это та же модель, что у апстримного
`freezeColumns` (клип прокручиваемых колонок по краю зоны), только край зоны считается на каждый кадр.

Вся математика в `render/data-grid-freeze.ts`:

| Что | Назначение |
|---|---|
| `StickyAxis` | Одна ось (строки или колонки): слоты, позиции, `pinnedCount`, край зоны `pinnedEnd`, `maxEnd` (все прилипли), hit-test `pinnedAt`, фрагменты блоков `pinnedRun` |
| `computeColumnLayout` | Раскладка колонок на кадр: `effectiveCols` (сначала прилипшие, потом видимые прокручиваемые), `drawX` по `sourceIndex`, `isPinned` |
| `computeRowAxis` | Ось строк: позиции считаются от `cellYOffset`, строка выше него уже прилипла; ниже — проход по видимым строкам. На кадре нет циклов по всем строкам таблицы |
| `columnLayoutOf` / `rowAxisOf` | Раскладка кадра едет вместе с массивом `effectiveCols`, поэтому обходчики берут её без нового параметра. Для массивов, собранных вручную, работает апстримное накопление ширин |

Внутри кадра у колонок из `effectiveCols` флаг `sticky` значит «прилипла сейчас»: неприлипшая липкая
колонка отдаётся копией с `sticky: false`, и апстримный код (клипы, colspan, fill handle) работает без правок.

Строки обходятся тремя секциями (`walkRowsInCol`): прокручиваемые (без прилипших и без целиком ушедших
под полосу), прилипшие сверху и закреплённые снизу. Прилипшие рисуются с `isSticky`, то есть с
непрозрачным фоном поверх того, что прокрутилось под них, — как апстрим рисует закреплённые снизу.

Blit: по X ширина неподвижной зоны = край прилипших колонок; если колонка прилипла или отлипла между
кадрами, кадр перерисовывается целиком. По Y полоса строк (по максимуму, когда прилипли все) не
копируется, а перерисовывается.

## 4. Ограничения

- Colspan (`span`), пересекающий внутреннюю липкую колонку, делится на закреплённую и прокручиваемую
  части по префиксу `freezeColumns`, как в апстриме; внутренние липкие колонки внутри colspan не поддержаны.
- `verticalBorder(index + 1)` в линиях сетки получает индекс среди видимых колонок, а не `sourceIndex` —
  так было в апстриме; с липкими колонками расхождение заметнее. Не меняли, чтобы не задеть текущие экраны.
