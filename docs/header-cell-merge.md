# Объединение ячеек шапки — документация правок форка

Этот документ описывает, **что мы доработали в форке glide** для слияния ячеек шапки таблицы.
Это **не** нативное поведение glide — фича добавлена поверх. Здесь подробно: в чём проблема,
что было нативным и что добавили мы, публичный API, как это работает, поведение (клики,
наведение, выделение) и карта кода по модулям.

Планы, отложенное и известные баги — в `plans/header-cell-merge.md`.

---

## 1. Проблема и решение

Когда в таблице включена **группировка колонок**, у шапки появляются верхние **групп-ряды**
(сколько рядов — столько, какова глубина самой длинной ветки групп). Из-за этого возникают
пустые ячейки:

**(а) одиночная колонка (без группы)** — над её заголовком пустая ячейка в групп-ряду:

```
┌────────┬────────┬───────────────────────────┐
│ (пусто)│ (пусто)│            KPI            │   ← ряд групп
├────────┼────────┼───────┬────────┬──────────┤
│  Роль  │ Период │  Инд  │  Кол   │  Оценка  │   ← ряд колонок
└────────┴────────┴───────┴────────┴──────────┘
```

**(б) «мелкая» группа** (её глубина меньше самой длинной ветки) — под её заголовком пустой ряд:

```
┌───────────────────────────┬───────────────┐
│            KPI            │     2024      │   ← level 0
├───────┬────────┬──────────┼───────────────┤
│(пусто)│ (пусто)│ (пусто)  │      Q1       │   ← level 1: под KPI пусто
├───────┼────────┼──────────┼───────┬───────┤
│  Инд  │  Кол   │  Оценка  │ Q1-A  │ Q1-B  │   ← ряд колонок
└───────┴────────┴──────────┴───────┴───────┘
```

**Решение** — слить эти пустые ряды в одну высокую ячейку (и при желании выровнять контент
по двум осям):

```
(а) spanGroupHeader             (б) span / spanShallowGroups
┌────────┬────────┬─────────┐   ┌───────────────────────────┬───────────────┐
│        │        │   KPI   │   │                           │     2024      │
│  Роль  │ Период ├───┬──┬──┤   │            KPI            ├───────────────┤
│        │        │Инд│Кол│Оц│  │                           │      Q1       │
└────────┴────────┴───┴──┴──┘   ├───────┬────────┬──────────┼───────┬───────┤
                                │  Инд  │  Кол   │  Оценка  │ Q1-A  │ Q1-B  │
                                └───────┴────────┴──────────┴───────┴───────┘
```

Важно: слияние группы **доходит до ряда колонок, но НЕ включает его** (колонки остаются
отдельными). Всё включается по желанию (opt-in): не задал флаг — отрисовка байт-в-байт как
в апстриме.

## 2. Что нативное в glide, а что добавили МЫ

Механику **группировки** мы не меняли — только расширили её. Сверено по `origin/main` апстрима.

| Уже было в glide (нативное) | Добавили МЫ (форк) |
|---|---|
| поле `group` на колонке | `spanGroupHeader` — слить одиночную колонку |
| проп `getGroupDetails` + тип `GroupDetails` | поля `span` и `spanAlign` внутри `GroupDetails` |
| отрисовка групп-шапок, `walkGroups`, индексы рядов | `spanShallowGroups`, `spanAlign` (пропы `DataEditor`) |
| диапазон колонок группы `span: [start, end]` | `spanGroupHeaderAlign` (на колонке) |
| — | `getSpannedGroupRegions`, `drawSpanAlignedText`, `resolveSpanAlignment`, `getSpanTextY`, `segmentSpanGroupHeaderLine` |

**Ряды шапки нумеруются отрицательными индексами** (это важно для кликов, наведения и поиска
ячейки): `-1` — ряд колонок; `-2 - level` — ряды групп (`level 0` → `-2`, следующий `-3` и так
далее).

## 3. Публичный API

Три уровня задания — колонка, группа, грид. Значение на колонке или группе важнее, чем
grid-дефолт.

### 3.1 Листовая колонка (`spanGroupHeader`)
Флаг **на колонке** (без группы) — рисует её шапку как одну ячейку на всю высоту:
```tsx
columns={[
  { title: 'Роль',   spanGroupHeader: true },
  { title: 'Период', spanGroupHeader: true },
  { title: 'Инд', group: 'KPI' },
]}
```
Или grid-дефолт сразу на все листья (с точечным отключением):
```tsx
<DataEditor
  spanGroupHeader                                  // все листья без группы — слиты
  columns={[
    { title: 'Роль' },                             // слито (grid-дефолт)
    { title: 'Период', spanGroupHeader: false },   // точечно отключено → НЕ слито
    { title: 'Инд', group: 'KPI' },
  ]}
/>
```
Действует только для колонки БЕЗ группы (у сгруппированной флаг игнорируется).

### 3.2 «Мелкая» группа (`span` / `spanShallowGroups`)
Точечно на группе через `getGroupDetails` или общим пропом на все мелкие группы:
```tsx
<DataEditor
  columns={columns}
  spanShallowGroups                                // все мелкие группы сливают пустые ряды
  getGroupDetails={name => (name === 'KPI' ? { name, span: false } : { name })} // KPI — исключить
/>
```
Приоритет: `getGroupDetails(name).span` важнее общего `spanShallowGroups` (точечный `false`
отключает). Защита от «рваной» глубины: группу сливаем вниз только если у ВСЕХ её колонок нет
более глубокой подгруппы.

### 3.3 Выравнивание (`spanAlign` / `spanGroupHeaderAlign`)
Выравнивание текста по двум осям внутри слитой ячейки. `SpanAlignment = { horizontal?, vertical? }`,
`horizontal: 'left'|'center'|'right'`, `vertical: 'top'|'center'|'bottom'`.
```tsx
<DataEditor
  spanAlign={{ horizontal: 'center', vertical: 'center' }}   // общий дефолт
  columns={[
    { title: 'Итого', spanGroupHeader: true,
      spanGroupHeaderAlign: { horizontal: 'right', vertical: 'bottom' } },  // точечно на колонке
  ]}
  getGroupDetails={name => name === 'KPI'
    ? { name, span: true, spanAlign: { horizontal: 'center', vertical: 'top' } }  // точечно на группе
    : { name }}
/>
```
Приоритет: колонка/группа → общий `spanAlign` → значение по умолчанию (лист слева, группа по
центру; по вертикали по центру). Можно задать только одну ось — вторая берётся по умолчанию.
Письмо справа налево (RTL) пока не поддержано (рисуем без выравнивания).

## 4. Как это работает (цепочка отрисовки)

```
[1] Читаем колонки и их group (нативно) → глубина групп, ряды групп (нативно glide)
        │
[2] НАШЕ: ищем, что слить (getSpannedGroupRegions + флаг spanGroupHeader на листе)
        • листовые колонки со spanGroupHeader
        • мелкие группы со span/spanShallowGroups (с защитой от рваной глубины)
        │
[3] НАШЕ: рисуем слитые ячейки на суммарную высоту (mergedHeight); пустые ряды под ними
        пропускаем; линии между уровнями режем по x-диапазону слитого (segmentSpanGroupHeaderLine)
        │
[4] НАШЕ: если задано выравнивание — ставим текст по осям (drawSpanAlignedText/getSpanTextY)
```

Один и тот же список областей из шага [2] используют отрисовка, клики, наведение и границы —
чтобы они не разошлись между собой (**единый источник**). При этом spanGroupHeader-колонка НЕ
входит ни в какую группу: в `walkGroups` она разрывает пустой («») групп-спан с обеих сторон.

## 5. Поведение (клики / попадание клика / наведение / выделение)

- **Клик и наведение в любую точку** слитой листовой ячейки трактуются как ряд колонки (`-1`),
  то есть клик по шапке этой колонки. Для слитой группы — как групп-ряд её уровня (`-2 - L`),
  то есть клик по группе. Нормализацию делает `getMouseArgsForPosition` (переносит `row` к
  первой ячейке слитого блока).
- **Наведение** подсвечивает всю слитую ячейку целиком (не отдельно верх и пустой ряд).
- **Смешанный случай** (слитая листовая ячейка рядом с НЕслитой безгруппной — например, точечно
  отключили): обе без группы, то есть в одном пустом («») спане. spanGroupHeader-колонка его
  разрывает, поэтому пустая групп-ячейка, наведение и обрезка не залезают на слитую. Клик по
  пустой («») групп-ячейке соседней НЕслитой колонки ничего не делает (пустая группа — не
  группа: ничего не выделяем и слитого соседа не прихватываем). Выделение настоящих групп — как
  раньше.

## 6. Карта кода (что где)

Фича размазана по модулям `packages/core/src`:

- **`internal/data-grid/data-grid-types.ts`** — поля и типы: `spanGroupHeader`/`spanGroupHeaderAlign`
  на колонке; `span`/`spanAlign` в `GroupDetails`; `SpanAlignment` и типы осей.
- **`data-editor/data-editor.tsx`** — публичные пропы `spanShallowGroups`/`spanAlign`/`spanGroupHeader`
  и раздача их вниз; `mangledGetGroupDetails` (значения по умолчанию `span ?? spanShallowGroups`,
  `spanAlign ?? spanAlign` для групп); `handleGroupHeaderSelection` (по пустой «» группе ничего
  не делаем).
- **`internal/data-grid/data-grid.tsx`** — пропы у `DataGrid`; `getMouseArgsForPosition`
  (перенос клика/наведения к первой ячейке слитого блока).
- **Три обёртки** `internal/data-grid-search` → `scrolling-data-grid` → `data-grid-dnd` —
  проброс grid-пропов **явными списками** (не через `{...rest}`).
- **`internal/data-grid/render/data-grid-lib.ts`** — `useMappedColumns` (нормализация флага +
  значение `spanAlign` по умолчанию для листьев); `resolveSpanAlignment` / `getSpanTextY` /
  `drawSpanAlignedText` (общий помощник выравнивания по двум осям); `computeBounds` (границы

- **`internal/data-grid/render/data-grid-render.walk.ts`** — `getSpannedGroupRegions`
  (логические области слитых групп), `walkGroups` (разрыв «»-спана на spanGroupHeader),
  `getGroupAtLevel`.
- **`internal/data-grid/render/data-grid-render.header.ts`** — `drawGridHeaders` (лист на всю
  высоту), `drawGroupLevel`/`drawGroupHeaderInner` (слитая группа, акцент/наведение,
  выравнивание), `segmentSpanGroupHeaderLine` (разрез линии между уровнями по x-диапазонам
  слитых).
- **`internal/data-grid/render/data-grid-render.ts`** — `clipHeaderDamage` (обрезка слитой
  колонки на всю высоту + пропуск allSpanned, см. §7).

## 7. Правило, которое нельзя нарушать: частичная перерисовка (damage) и обрезка

Дальше зовём частичную перерисовку области словом **damage** — это способ glide перерисовать
только задетый кусок, а не всю шапку.

**Правило:** `clipHeaderDamage` (проход по группам через `walkGroups`) и `drawGroupLevel`
обязаны одинаково пропускать `allSpanned`-спаны (это групп-спан, где ВСЕ колонки —
`spanGroupHeader`). Обе точки помечены перекрёстными комментариями в коде.

**Почему (баг, который чинили):** наводим на соседнюю группу — damage задевает её групп-ряд.
Пустой групп-спан из слитых колонок `drawGroupLevel` НЕ рисует (пропускает как `allSpanned` —
групп-ряд слитой колонки восстанавливает её собственная перерисовка на всю высоту). Если
`clipHeaderDamage` этот спан НЕ пропускает, он ставит обрезку на его групп-полосу, и очистка
фона `fillRect(0,0,width,total)` внутри обрезки **стирает верхнюю полосу слитой ячейки**, а
восстановить её некому. Итог: серая полоса поверх текста и исчезнувшая вертикальная линия.
Фикс структурный — покрывает любой случай задетого соседа.

## 8. Пост-релизные правки (после 6.1.0)

Ветка `fix/span-group-header-prop-forwarding`:

- **Проброс grid-пропа.** `spanGroupHeader`/`spanAlign` терялись между `DataEditor` и `DataGrid`,
  потому что три обёртки (`DataGridSearch`/`ScrollingDataGrid`/`DataGridDnd`) пробрасывают пропы
  **явными списками**, а эти пропы туда не добавили. Задание на колонке работало (едет в массиве
  `columns`), а grid-дефолт молча нет. TypeScript это не поймал: типы обёрток наследуются вниз до
  `DataGridProps`, поэтому проп структурно есть, а забытый проброс необязательного пропа — не
  ошибка. Тесты тоже не поймали: они дёргали `useMappedColumns`/рендер напрямую, минуя цепочку
  обёрток. **Фикс:** добавить проброс в трёх обёртках + интеграционный тест с монтированием
  (`<DataEditor spanGroupHeader>` → `getBounds` через всю цепочку).
- **Смешанный «»-спан.** Слитая листовая колонка рядом с НЕслитой безгруппной (например,
  точечно отключили) делили один пустой («») групп-спан. Пропуск `allSpanned` покрывал только
  случай «все слиты», а смешанный протекал (пустая ячейка, наведение или обрезка залезали на
  слитую, клик выделял и соседа). **Фикс:** `walkGroups` не сливает spanGroupHeader-колонку с
  соседями (отрисовка/обрезка/наведение); клик по пустой «» группе ничего не делает (выделение).

Ветка `fix/group-header-theme-padding` (glide 6.1.2):

- **Отступы обычной групп-шапки из темы.** Горизонтальный отступ обычной групп-шапки и геометрия
  её иконки были жёстко зашиты (`xPad = 8`, размер иконки `20`, сдвиг под текст `26`), тогда как
  заголовки колонок (`computeHeaderLayout`) и уже-слитая группа (ветка `else` в
  `drawGroupHeaderInner`) берут их из темы. На размерах, где `cellHorizontalPadding !== 8`
  (в потребителе `@daisforge/ui` small=4 / medium=8 / big=16), групповой заголовок не совпадал с
  колонками по левому краю (на `big` колонки на 16px, а группа на 8px). **Фикс:**
  `xPad = theme.cellHorizontalPadding`; иконка рисуется размером `theme.headerIconSize`, сдвиг
  под текст — `Math.ceil(headerIconSize * 1.3)` (тот же расчёт, что у колонок; `26 = ceil(20 × 1.3)`).
  Иконки у групп сейчас не используются — правку размера и сдвига иконки делаем на будущее, чтобы
  группа и колонки шли из одного источника.

Ветка `fix/header-first-column-borders` (glide 6.1.6):

- **Проблеск цвета наведения на групп-шапке.** При наведении на групп-ячейку (в том числе на
  подгруппу) первый кадр приходит с `hoverAmount === 0` (анимация ещё не стартовала, но
  `isHovered` уже true) и попадал в ветку `else` заливки фона в `drawGroupLevel`, а та красит
  `bgGroupHeaderHovered` **на полной непрозрачности** — вспышка, потом падение в alpha ~0.2 и
  плавный набор обратно. Ветка `else` (непрозрачно) нужна только выделению (`accentColor`, там
  `hoverAmount` принудительно 0), но ловила ещё и «наведение до старта анимации». **Фикс:**
  `else if (isSelected || !isHovered)` — непрозрачно красим только выделение и обычный фон группы
  (`bgGroupHeader`), а кадр «наведение при hoverAmount === 0» пропускаем (плавное появление идёт
  с нуля). Грабля: вариант `if (isSelected)` выкидывал обычный фон, и у выделенной подгруппы
  пропадала заливка; правильное условие — `isSelected || !isHovered`.
- **Ложная левая вертикаль слитого кастом-нейма на первой позиции.** Закрывающий штрих уровня в
  `drawGroupLevel` (`ctx.moveTo(finalX + 0.5, …)`) рисовался всегда, а `finalX` начинается с 0 и
  сдвигается только на обработанной группе. При частичной перерисовке (damage при наведении) все
  группы уровня отфильтровываются проверкой damage, поэтому `finalX` остаётся 0, и штрих на
  `x = 0.5` рисует лишнюю вертикаль на левом краю шапки. Видно только на первой позиции (там стоит
  слитая ячейка; в другом месте `x = 0.5` — это рамка таблицы). Это НЕ строка 697 (при `x = 0`
  `willStroke = false`) и НЕ dpr (воспроизводится и на целом `dpr = 4`). **Фикс:** рисовать
  закрывающий штрих только при `finalX > 0` (в полной отрисовке группа всегда есть, границы на
  месте; `finalX === 0` значит закрывать нечего).

Ветка `fix/dnd-group-structure` (glide 6.1.8):

- **Слияние группы ломается ВО ВРЕМЯ перетаскивания колонок.** Тащишь лист (например, кастом-нейм
  TR) в середину другой группы — превью рисуется сломанно (пустая полоса у слитой ячейки, битое
  слияние), хотя ПОСЛЕ отпускания та же структура рисуется чисто. Причина: `getSpannedGroupRegions`
  (`data-grid-render.walk.ts`) определял «терминальность» слитой группы циклом
  `for (i = span[0]; i <= span[1]) effectiveCols[i]`, где `span` — концы в **sourceIndex**, а
  `effectiveCols` индексируется по **позиции**. Во время перетаскивания `remapForDnDState`
  переставляет колонки, но `sourceIndex` остаётся исходным (он нужен, чтобы данные тела ехали за
  колонкой), поэтому `позиция ≠ sourceIndex`, цикл читал не те колонки и ошибочно отбрасывал
  область слияния. После отпускания `useMappedColumns` даёт свежий `sourceIndex = i` — всё сходится.
  **Фикс:** `walkGroups` считает флаг `spanHasDeeperGroup` по фактическим колонкам-позициям (тот
  же приём, что уже был для `spanAllSpanned` — «не циклом по source-диапазону»), а
  `getSpannedGroupRegions` использует флаг вместо битого цикла. Это тот же класс, что баг
  «групп-шапка мигает пустой при перетаскивании» (findings-док про span в sourceIndex-координатах).

  **Скрытый родственник (НЕ трогали, задокументировано на будущее): `getSpanBounds`.** Он тоже
  ходит по `allColumns[x]`, где `x` крутится от `column.sourceIndex` — та же болячка «sourceIndex
  как позиция». Зовётся из ДВУХ мест, оба про слитые ячейки ТЕЛА (`cell.span`, colspan): отрисовка
  (`data-grid-render.cells.ts:242`) и рамки фокуса/выделения (`data-grid.render.rings.ts:278`).
  Значит всплывёт ТОЛЬКО когда: (1) есть colspan-ячейки тела (`cell.span`) И (2) идёт перетаскивание
  колонок — тогда во время превью геометрия, заливка и рамка слитой ячейки тела посчитаются по НЕ
  тем колонкам. Слитой ШАПКИ не касается (там `walkGroups`/области, уже починены) и после отпускания
  не проявляется (`sourceIndex` снова равен позиции). Фикс по аналогии: считать геометрию по
  фактическим колонкам спана (по позициям), а не крутить индекс от `sourceIndex`. Приоритет низкий
  (нужны И colspan-тело, И перетаскивание).

Ветка `feat/span-cells` (поверх 6.1.8) — попутные правки шапки при работе над слитыми
ячейками тела:

- **Обрезка damage шапки протекала в соседний групп-ряд** (`dee4f02`). Запас на восстановление
  у damage-областей стал ненулевым и без low-DPR (он нужен для границ слитых ячеек ТЕЛА), и общий
  запас раздувал заодно `clipHeaderDamage`. При наведении на лист под выделенной группой очистка
  фона внутри раздутой обрезки рисовала светлую полосу на групп-ряду. **Фикс:** запасы разделены —
  `getDamageRepairPad` (шапка) остаётся 0 без low-DPR (плотная обрезка), а тело добирает свой
  запас ≥ 1 локально через `getBodyDamagePad` (см. `docs/body-cell-merge.md` §7-б).
- **Вспышка наведения на групп-шапке при выделении** (`8ecfddf`). На damage при наведении
  групп-ячейка сперва очищается в `bgHeader` (самый светлый цвет), и кадр «наведение при
  `hoverAmount === 0`», который фикс 6.1.6 просто пропускал, оставлял этот яркий фон видимым —
  вспышка при уходе наведения с выделенной группы. **Фикс структурный (заменяет ветвление 6.1.6):**
  базовый (не-hover) цвет группы красится ВСЕГДА непрозрачно, а цвет наведения накладывается сверху
  отдельным слоем с `alpha = hoverAmount`. При `ha = 0` виден базовый фон (нет вспышки), при `ha = 1`
  — полное наведение (нет и старого «проблеска»). Тесты на регресс:
  `data-grid-render.group-hover-flicker.test.ts`, `group-selection-fill-border.test.ts`.
