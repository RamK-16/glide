# Объединение ячеек шапки — документация правок форка

Этот документ описывает, **что мы доработали в форке glide** для объединения (слияния)
ячеек шапки таблицы. Это **не** нативное поведение glide — фича добавлена поверх. Здесь —
подробное описание: проблема, что нативное vs что добавили мы, публичный API, как это работает,
поведение (клики/hover/выделение) и карта кода по модулям.

Планы, отложенное и известные баги — в `plans/header-cell-merge.md`.

---

## 1. Проблема и решение

Когда в таблице включена **группировка колонок**, шапка получает верхние **групп-ряды**
(число рядов = глубина самой длинной ветки групп). Из-за этого появляются пустые ячейки:

**(а) одиночная колонка (без группы)** — над её заголовком пустая ячейка в групп-ряду:

```
┌────────┬────────┬───────────────────────────┐
│ (пусто)│ (пусто)│            KPI            │   ← ряд групп
├────────┼────────┼───────┬────────┬──────────┤
│  Роль  │ Период │  Инд  │  Кол   │  Оценка  │   ← ряд колонок
└────────┴────────┴───────┴────────┴──────────┘
```

**(б) «мелкая» группа** (глубина меньше самой длинной ветки) — под её заголовком пустой ряд:

```
┌───────────────────────────┬───────────────┐
│            KPI            │     2024      │   ← level 0
├───────┬────────┬──────────┼───────────────┤
│(пусто)│ (пусто)│ (пусто)  │      Q1       │   ← level 1: под KPI пусто
├───────┼────────┼──────────┼───────┬───────┤
│  Инд  │  Кол   │  Оценка  │ Q1-A  │ Q1-B  │   ← ряд колонок
└───────┴────────┴──────────┴───────┴───────┘
```

**Решение** — слить эти пустые ряды в одну высокую ячейку (и опц. выровнять контент по 2 осям):

```
(а) spanGroupHeader             (б) span / spanShallowGroups
┌────────┬────────┬─────────┐   ┌───────────────────────────┬───────────────┐
│        │        │   KPI   │   │                           │     2024      │
│  Роль  │ Период ├───┬──┬──┤   │            KPI            ├───────────────┤
│        │        │Инд│Кол│Оц│  │                           │      Q1       │
└────────┴────────┴───┴──┴──┘   ├───────┬────────┬──────────┼───────┬───────┤
                                │  Инд  │  Кол   │  Оценка  │ Q1-A  │ Q1-B  │
                                └───────┴────────┴──────────┴───────┴───────┘
```

Важно: слияние группы **доходит до ряда колонок, но НЕ включает его** (колонки остаются
отдельными). Всё **opt-in**: не задал флаг — рендер байт-в-байт как в апстриме.

---

## 2. Что нативное в glide, а что добавили МЫ

Механику **группировки** мы не меняли — только расширили её. Сверено по `origin/main` апстрима.

| Уже было в glide (нативное) | Добавили МЫ (форк) |
|---|---|
| поле `group` на колонке | `spanGroupHeader` — слить одиночную колонку |
| проп `getGroupDetails` + тип `GroupDetails` | поля `span` и `spanAlign` внутри `GroupDetails` |
| отрисовка групп-шапок, `walkGroups`, индексы рядов | `spanShallowGroups`, `spanAlign` (пропы `DataEditor`) |
| диапазон колонок группы `span: [start, end]` | `spanGroupHeaderAlign` (на колонке) |
| — | `getSpannedGroupRegions`, `drawSpanAlignedText`, `resolveSpanAlignment`, `getSpanTextY`, `segmentSpanGroupHeaderLine` |

**Ряды шапки нумеруются отрицательными индексами** (важно для кликов/hover/поиска ячейки):
`-1` — ряд колонок; `-2 - level` — ряды групп (`level 0` → `-2`, следующий `-3`, …).

## 3. Публичный API

Три уровня задания — колонка / группа / грид. Значение на колонке/группе важнее grid-дефолта.

### 3.1 Листовая колонка (`spanGroupHeader`)
Флаг **на колонке** (без группы) — рисует её шапку как одну ячейку на всю высоту:
```tsx
columns={[
  { title: 'Роль',   spanGroupHeader: true },
  { title: 'Период', spanGroupHeader: true },
  { title: 'Инд', group: 'KPI' },
]}
```
Или grid-дефолт на все листья сразу (с точечным опт-аутом):
```tsx
<DataEditor
  spanGroupHeader                                  // все листья без группы — слиты
  columns={[
    { title: 'Роль' },                             // слито (grid-дефолт)
    { title: 'Период', spanGroupHeader: false },   // точечный опт-аут → НЕ слито
    { title: 'Инд', group: 'KPI' },
  ]}
/>
```
Действует только для колонки БЕЗ группы (у сгруппированной флаг игнорируется).

### 3.2 «Мелкая» группа (`span` / `spanShallowGroups`)
Точечно на группе через `getGroupDetails`, либо общим пропом на все мелкие группы:
```tsx
<DataEditor
  columns={columns}
  spanShallowGroups                                // все мелкие группы сливают пустые ряды
  getGroupDetails={name => (name === 'KPI' ? { name, span: false } : { name })} // KPI — исключить
/>
```
Приоритет: `getGroupDetails(name).span` важнее общего `spanShallowGroups` (точечный `false` отключает).
Ragged-guard: группу сливаем вниз только если у ВСЕХ её колонок нет более глубокой подгруппы.

### 3.3 Выравнивание (`spanAlign` / `spanGroupHeaderAlign`)
2D-выравнивание текста внутри слитой ячейки. `SpanAlignment = { horizontal?, vertical? }`,
`horizontal: 'left'|'center'|'right'`, `vertical: 'top'|'center'|'bottom'`.
```tsx
<DataEditor
  spanAlign={{ horizontal: 'center', vertical: 'center' }}   // общий дефолт
  columns={[
    { title: 'Итого', spanGroupHeader: true,
      spanGroupHeaderAlign: { horizontal: 'right', vertical: 'bottom' } },  // точечно на колонке
  ]}
  getGroupDetails={name => name === 'KPI'
    ? { name, span: true, spanAlign: { horizontal: 'center', vertical: 'top' } }  // точечно на группе
    : { name }}
/>
```
Приоритет: колонка/группа → общий `spanAlign` → дефолт (лист слева, группа по центру; вертикаль
по центру). Можно задать только одну ось — вторая берётся по умолчанию. RTL пока не поддержан
(рисуем без выравнивания).

## 4. Как это работает (пайплайн)

```
[1] Читаем колонки и их group (нативно) → глубина групп, ряды групп (нативно glide)
        │
[2] НАШЕ: ищем, что слить (getSpannedGroupRegions + флаг spanGroupHeader на листе)
        • листовые колонки со spanGroupHeader
        • мелкие группы со span/spanShallowGroups (с ragged-guard)
        │
[3] НАШЕ: рисуем слитые ячейки на суммарную высоту (mergedHeight); пустые ряды под ними
        пропускаем; межуровневые линии режем по x-диапазону слитого (segmentSpanGroupHeaderLine)
        │
[4] НАШЕ: если задано выравнивание — ставим текст по осям (drawSpanAlignedText/getSpanTextY)
```

Один и тот же список регионов из шага [2] используют отрисовка, клики, hover и границы — чтобы
они не рассинхронились (**единый источник**). spanGroupHeader-колонка при этом НЕ входит ни в
какую группу: в `walkGroups` она разрывает пустой («») групп-спан с обеих сторон.

## 5. Поведение (клики / hit-test / hover / выделение)

- **Клик/hover в любую точку** слитой листовой ячейки → трактуется как ряд колонки (`-1`) →
  header-клик по этой колонке. Слитой группы → групп-ряд её уровня (`-2 - L`) → group-клик.
  Нормализация — в `getMouseArgsForPosition` (ремап `row` к origin слитой ячейки).
- **hover** подсвечивает всю слитую ячейку целиком (не отдельно верх и пустой ряд).
- **Смешанный случай** (слитая листовая рядом с НЕслитой безгруппной — напр. точечный опт-аут):
  обе без группы, т.е. в одном пустом («») спане. spanGroupHeader-колонка его разрывает, поэтому
  пустая групп-ячейка/hover/клип не залезают на слитую. Клик по пустой («») групп-ячейке соседней
  НЕслитой колонки — **no-op** (пустая группа не группа: ничего не выделяем, слитого соседа не
  прихватываем). Выделение настоящих групп — как раньше.

## 6. Карта кода (что где)

Фича размазана по модулям `packages/core/src`:

- **`internal/data-grid/data-grid-types.ts`** — поля/типы: `spanGroupHeader`/`spanGroupHeaderAlign`
  на колонке; `span`/`spanAlign` в `GroupDetails`; `SpanAlignment` и типы осей.
- **`data-editor/data-editor.tsx`** — публичные пропы `spanShallowGroups`/`spanAlign`/`spanGroupHeader`
  и раздача вниз; `mangledGetGroupDetails` (дефолты `span ?? spanShallowGroups`, `spanAlign ?? spanAlign`
  для групп); `handleGroupHeaderSelection` (пустая «» группа — no-op).
- **`internal/data-grid/data-grid.tsx`** — пропы у `DataGrid`; `getMouseArgsForPosition` (нормализация
  клика/hover к origin слитой ячейки).
- **Три обёртки** `internal/data-grid-search` → `scrolling-data-grid` → `data-grid-dnd` — проброс
  grid-пропов **явными списками** пропов (не `{...rest}`).
- **`internal/data-grid/render/data-grid-lib.ts`** — `useMappedColumns` (нормализация флага + дефолт
  `spanAlign` для листьев); `resolveSpanAlignment` / `getSpanTextY` / `drawSpanAlignedText` (единый
  помощник 2D-выравнивания); `computeBounds` (bounds слитой ячейки на всю высоту).
- **`internal/data-grid/render/data-grid-render.walk.ts`** — `getSpannedGroupRegions` (логические
  регионы слитых групп), `walkGroups` (разрыв «»-спана на spanGroupHeader), `getGroupAtLevel`.
- **`internal/data-grid/render/data-grid-render.header.ts`** — `drawGridHeaders` (лист на всю высоту),
  `drawGroupLevel`/`drawGroupHeaderInner` (слитая группа, accent/hover, выравнивание),
  `segmentSpanGroupHeaderLine` (разрез межуровневой линии по x-диапазонам слитых).
- **`internal/data-grid/render/data-grid-render.ts`** — `clipHeaderDamage` (клип слитой колонки на
  всю высоту + allSpanned-скип, см. §7).

## 7. ⚠️ Инвариант damage/clip (дорого далось — НЕ сломать)

**Правило:** `clipHeaderDamage` (групп-цикл по `walkGroups`) и `drawGroupLevel` ОБЯЗАНЫ одинаково
пропускать `allSpanned`-спаны (групп-спан, где ВСЕ колонки — `spanGroupHeader`). Обе точки помечены
перекрёстными комментариями в коде.

**Почему (баг, который чинили):** наводим на соседнюю группу → damage задевает её групп-ряд. Пустой
групп-спан из слитых колонок `drawGroupLevel` НЕ рисует (скипает как `allSpanned` — групп-ряд слитой
колонки восстанавливает её собственная перерисовка на всю высоту). Если `clipHeaderDamage` этот спан
НЕ скипает → ставит клип на его групп-полосу → очистка фона `fillRect(0,0,width,total)` внутри клипа
**стирает верхнюю полосу слитой ячейки**, а восстановить некому. Итог: серая полоса поверх текста +
исчезнувшая вертикальная линия. Фикс структурный — покрывает любой случай задетого соседа.

## 8. Пост-релизные правки (после 6.1.0)

Ветка `fix/span-group-header-prop-forwarding`:

- **Forwarding grid-пропа.** `spanGroupHeader`/`spanAlign` теряются между `DataEditor` и `DataGrid`,
  потому что три обёртки (`DataGridSearch`/`ScrollingDataGrid`/`DataGridDnd`) пробрасывают пропы
  **явными списками**, и в них эти пропы не добавили. Per-column работал (едет в массиве `columns`),
  grid-дефолт — молча нет. TypeScript не поймал: типы обёрток наследуются вниз до `DataGridProps`, так
  что проп структурно есть, а пропущенный форвардинг опционального пропа — не ошибка. Тесты не поймали:
  дёргали `useMappedColumns`/рендер напрямую, минуя цепочку обёрток. **Фикс:** добавить форвардинг в
  трёх обёртках + монтирующий интеграционный тест (`<DataEditor spanGroupHeader>` → `getBounds` через
  всю цепочку).
- **Смешанный «»-спан.** Слитая листовая колонка рядом с НЕслитой безгруппной (напр. опт-аут) делили
  один пустой («») групп-спан; `allSpanned`-скип покрывал только «все слиты», а смешанный протекал
  (пустая ячейка/hover/клип поверх слитой, клик выделял и соседа). **Фикс:** `walkGroups` не сливает
  spanGroupHeader-колонку с соседями (render/clip/hover); клик по пустой «» группе — no-op (selection).

Ветка `fix/group-header-theme-padding` (glide 6.1.2):

- **Отступы обычной групп-шапки из темы.** Горизонтальный отступ обычной групп-шапки и геометрия её
  иконки были захардкожены (`xPad = 8`, размер иконки `20`, сдвиг под текст `26`), тогда как заголовки
  колонок (`computeHeaderLayout`) и уже-слитая группа (ветка `else` в `drawGroupHeaderInner`) берут их
  из темы. На размерах, где `cellHorizontalPadding !== 8` (в потребителе `@daisforge/ui` small=4 /
  medium=8 / big=16), групповой заголовок рассинхронивался с колонками по левому краю (на `big` колонки
  на 16px, а группа — на 8px). **Фикс:** `xPad = theme.cellHorizontalPadding`; иконка рисуется размером
  `theme.headerIconSize`, сдвиг под текст — `Math.ceil(headerIconSize * 1.3)` (тот же расчёт, что у
  колонок; `26 = ceil(20 × 1.3)`). Иконки у групп сейчас не используются — правку размера/сдвига иконки
  делаем на будущее, чтобы группа и колонки шли из одного источника.
