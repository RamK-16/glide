# План: rowspan для ГРУППОВЫХ ячеек шапки (отложено)

Статус: **PROPOSAL / отложено.** Не реализовано. Документ фиксирует кейс, оценку
стоимости и точки правки, чтобы вернуться, когда/если это потребуется дизайну.

---

## Что уже сделано (контекст)

Реализован флаг **`spanGroupHeader?: boolean`** на колонке (`BaseGridColumn`) —
«слитная шапка» для **листовой** колонки БЕЗ группы: её заголовок рисуется как одна
ячейка на всю высоту шапки (все групп-строки + строка колонки), с центрированием и
без разделительных линий поперёк.

Кейс, который это решает: одиночные колонки рядом со сгруппированными (напр. «Роль»,
«Период», «Продажи» рядом с группой «Коэффициент результативности [Индивид/Коллект/Оценка]»).
Раньше у них была пустая ячейка сверху + заголовок снизу — теперь единая ячейка.

Точки реализации (для справки, всё уже в ветке):
- `internal/data-grid/render/data-grid-render.header.ts` — `drawGridHeaders` (лист на всю
  высоту), `drawGroupLevel` (пропуск групп-ячейки над слитым листом),
  `drawGroups` (`segmentSpanGroupHeaderLine` — разрез межуровневой линии).
- `internal/data-grid/render/data-grid-lib.ts` — `useMappedColumns` (проброс флага!),
  `computeBounds` (bounds на всю высоту).
- `internal/data-grid/data-grid.tsx` — `getMouseArgsForPosition` (верх слитой = header).
- `internal/data-grid/render/data-grid-render.ts` — `clipHeaderDamage` (клип hover на всю высоту).

## Отложенный кейс: rowspan ГРУППЫ (не листа)

При многоуровневой шапке группа меньшей глубины оставляет под собой **пустую групп-строку**.

Пример (2 групп-уровня из-за `group: ["2024","Q1"]` у части колонок), а «Коэффициент
результативности» — одноуровневая группа (`group: "Коэффициент результативности"`):

```
│      2024      │ Коэффициент результативности │   ← level 0
│  Q1   │   Q2   │        (пусто)               │   ← level 1  ← ХОТИМ слить с level 0
│ A │ B │ C │ D  │ Индивид │ Коллект │ Оценка   │   ← строка колонок
```

`getGroupAtLevel("Коэффициент…", 1)` возвращает `""`, поэтому под группой рисуется пустая
ячейка. **Хотим:** групп-ячейка «Коэффициент результативности» занимает level 0 + level 1
(rowspan=2) как единая ячейка по центру над своими подколонками, но **НЕ** строку колонок
(под ней есть подколонки — Индивид/Коллект/Оценка).

Это отличается от листового `spanGroupHeader`:
- Лист (без группы) → спан на ВСЮ высоту (группы + строка колонки).
- Группа → спан только своих ПУСТЫХ нижних групп-уровней, остановка над подколонками.

**Сейчас нативно невозможно** — ни в glide, ни через `spanGroupHeader`.

## Почему отложено: дорого и багоёмко

У групп несравнимо больше обвязки, чем у листьев, и каждая точка — риск регрессии:

1. **Кросс-уровневая координация.** `drawGroupLevel` рисует каждый уровень независимо.
   Для слияния level-0 должен знать, что нижние уровни пусты для тех же колонок, и
   тянуться вниз; нижние уровни — пропускать уже покрытые ячейки. Это правка модели
   обхода (`walkGroups` / `drawGroups`), а не локальный тумблер.
2. **Ragged-случай.** Группа на level-0 покрывает колонки, где у ЧАСТИ есть более глубокие
   группы, а у части нет → чистого спана нет. Нужно правило: сливать вниз ТОЛЬКО если ВСЕ
   колонки спана пусты на нижележащих уровнях (иначе рисовать как сейчас).
3. **Сегментация межуровневых линий по уровням.** Резать нужно конкретную межуровневую
   линию под слитой группой на её x-диапазоне (не всю высоту, как у листа). Хелпер
   `segmentSpanGroupHeaderLine` переиспользуем, но вызывать пер-уровнево.
4. **Хит-тест/hover группы** (аналог сделанного Task IV для листьев, но для групп):
   попадание в нижнюю половину слитой группы → верхний групп-уровень (`-2 - topLevel`).
   Правки в `getMouseArgsForPosition` + `computeBounds` (bounds группы на слитую высоту) +
   `clipHeaderDamage` (клип группы на слитую высоту).
5. **Вся групповая машинерия на новой геометрии** — то, чего у листьев НЕТ:
   - `drawGroupHeaderCallback` (кастомный рендер группы) — rect слитой высоты;
   - group **actions** (иконки при hover) — позиционирование по слитой ячейке;
   - **rename** группы (`onGroupHeaderRenamed`, `group-rename.tsx`) — оверлей по слитой высоте;
   - **выделение всей группы** (highlight) — на слитую высоту;
   - тема из `getGroupDetails().overrideTheme`, hover-анимация.

**Оценка:** отдельная фича, ориентировочно **в 2–3× объёмнее и рискованнее**, чем листовой
`spanGroupHeader` (а там уже словили неочевидные баги: потерянный проброс флага в
`useMappedColumns`, клип hover в `clipHeaderDamage`). Основной багоёмкий фактор —
rename/actions/selection групп на изменённой высоте.

## Предлагаемый API (когда будем делать)

Два варианта, оба opt-in (нулевой риск для существующих таблиц):

- **Авто-режим:** «схлопывать пустые нижние групп-уровни в группу над ними». Включается
  пропом грида (напр. `collapseShallowGroups`/`spanShallowGroups`). Плюс — ничего не размечать
  вручную. Минус — меняет вид всех таблиц с неровной глубиной групп, поэтому только по флагу.
- **Явный флаг на группе:** через `getGroupDetails(name)` вернуть `{ span: true }`
  (в `GroupDetails`). Точечно, но требует, чтобы у группы был стабильный идентификатор.

Рекомендация: начать с явного `getGroupDetails().span` (меньше сюрпризов), авто-режим — опц.

## Когда имеет смысл (и когда нет)

**Имеет смысл**, если:
- Дизайн-макет требует, чтобы одноуровневая группа читалась как единый заголовок над
  подколонками в многоуровневой шапке (пустая ячейка под группой недопустима визуально).
- Таблицы со **смешанной глубиной** групп — частый паттерн в проекте.

**НЕ стоит лезть**, если:
- «Пустая ячейка под группой» визуально приемлема (частый случай — это косметика).
- Нет реального макета/требования — тогда риск (rename/actions/selection на новой высоте)
  не оправдан.

**Порядок:** сначала мёржим и стабилизируем листовой `spanGroupHeader` (законченная фича,
решает исходную задачу — одиночные колонки рядом с группой). Group-rowspan — отдельным PR,
после подтверждения дизайном, чтобы не смешивать риск и не конфликтовать с другими
правками рендера шапки.

## Переиспользуемое из листовой фичи
- `segmentSpanGroupHeaderLine(width, gaps)` — разрез горизонтальной линии по x-диапазонам.
- Паттерн «нормализовать хит-тест в верхнюю строку + bounds на слитую высоту + клип на
  слитую высоту» (Task IV: `getMouseArgsForPosition` / `computeBounds` / `clipHeaderDamage`).
- Принцип: всё за opt-in флагом, при отсутствии — поведение байт-в-байт прежнее.
